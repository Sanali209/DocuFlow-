# План доработки и расширения интерфейса DocuFlow (TDD + UX)

## 1. Контекст и мотивация
Анализ показал, что бэкенд (домен, парсеры, P2P) готов на 90%, однако UI содержит «заглушки» (статичные списки, неработающие фильтры, `location.reload()`). Выбрана комбинированная стратегия реализации: последовательное закрытие системных слоев, глубокая проработка модулей и финальная полировка пользовательских путей (ролей) через TDD.

## 2. Умственные эксперименты (Симуляция Use Cases) и Разрывы

### Use Case 1: Оператор (Смена, Пауза, Брак материала)
**Сценарий:** Оператор выбирает узел, берет батч. В процессе резки понимает, что лист металла с дефектом. Ставит задачу на паузу (указывает причину), списывает брак, передает смену с комментарием.
**Анализ текущего UI:** 
- Узлы захардкожены (LASER_1..4).
- При постановке на паузу нет быстрой кнопки «Списать брак / Запросить материал».
- Заметки о передаче смены сохраняются, но новому оператору они явно не выводятся поверх корзины при старте.
**Недостающий Backend/UI:**
- **Backend:** Интеграция `TaskItem` (пауза) и `MaterialAudit` (списание брака) в единый транзакционный флоу.
- **UI:** Алерт о принятой смене (с текстом от предыдущего оператора), динамический список узлов. Расширенный диалог паузы.

### Use Case 2: Бригадир (Планирование и Батчинг)
**Сценарий:** Бригадир видит новые наряды, фильтрует их по срочности. Выделяет задачи для `LASER_2`, собирает их в батчи с учетом остатков на складе (Stock Alerts).
**Анализ текущего UI:**
- Фильтры в `WorkItemsView` не работают (UI есть, логики нет).
- Авто-батчинг работает, но ручное формирование батчей (Drag & Drop или мультиселект) не реализовано в UI.
- Индикация `STOCK_ALERT` при батчинге отсутствует.
**Недостающий Backend/UI:**
- **Backend:** Полная логика применения фильтров в SQL-запросах (`WorkItemSystem.list_work_items_by_filter`).
- **UI:** Интерактивный UI для группировки задач (ручной батчинг), цветовая индикация нехватки материала до взятия в работу.

### Use Case 3: Начальник / Кладовщик (Склад и Сквозной Поиск)
**Сценарий:** Деталь (SKU) потерялась на производстве. Нужно узнать, в каком наряде она была и на какой паллете сейчас лежит.
**Анализ текущего UI:**
- Глобальный поиск и "Обратный поиск" (Part -> Pallet) заявлен в архитектуре, но в UI нет единой точки входа (Omnibar). Навигация раздроблена.
**Недостающий Backend/UI:**
- **Backend:** Сервис сквозного поиска (`SearchSystem`), агрегирующий данные из `WorkItem`, `PartLibrary` и `ProductionUnit`.
- **UI:** Компонент глобального поиска (Omnibar) в шапке `MainLayout`.

## 3. Анализ навигации и связности
- **Текущая проблема:** Навигация строго вертикальная (через боковое меню). Нельзя кликнуть на номер наряда в "Задачах" (TaskBoard) и перейти в "Карточку наряда" (WorkItems).
- **Решение (Deep Links):** Внедрить систему перекрестных ссылок внутри `switch_view`. Идентификаторы (work_item_id, task_item_id) должны быть кликабельными ссылками-событиями, программно меняющими активный view.
- **Устранение `location.reload()`:** Перевести все мутирующие действия (Start/Pause/Complete) на использование `@ui.refreshable` для локального обновления стейта компонентов без моргания экрана.

## 4. Пофазовый план реализации (TDD)

### Фаза 1: Горизонтальный фундамент (Backend + Reactivity)
**Цель:** Оживить мертвые зоны интерфейса, убрать хардкод и внедрить реактивность.
1. **Динамические узлы (TDD):**
   - *Тест:* Проверка, что оркестратор/админка возвращает актуальный список узлов (`Workplace`).
   - *Реализация:* Замена статического списка в `TaskBoardView._get_available_nodes`.
2. **Фильтрация нарядов (TDD):**
   - *Тест:* Убедиться, что `list_work_items_by_filter` корректно фильтрует по `status` и `search_text`.
   - *Реализация:* Привязка NiceGUI селекторов к `self.active_filters` с вызовом `self.render.refresh()`.
3. **Отказ от reload() в UI:**
   - *Реализация:* Обернуть `BucketPanel` и таблицу батчей в `@ui.refreshable`. Настроить коллбэки диалогов на вызов `refresh()`.

### Фаза 2: Вертикальные модули (Глубокая проработка UX)
**Цель:** Довести до идеала ключевые экраны согласно юзкейсам.
1. **Модуль TaskBoard (Бригадир):**
   - *Тест:* Создание ручного батча через API бэкенда (`BatchEngine.create_manual_batch`).
   - *UI:** Интерфейс для ручной группировки задач (мультивыбор -> "Объединить в батч"). Индикатор `STOCK_ALERT`.
2. **Сквозной поиск (Omnibar):**
   - *Тест:* Метод `search(query)` возвращает унифицированные DTO для Нарядов, Деталей и Паллет.
   - *UI:** Поисковая строка в 헤дере (Layout), выдающая выпадающий список с быстрыми ссылками (Deep Links).
3. **UNC Fallback в `ExplorerButton`:**
   - *Тест:* Имитация ошибки `subprocess.Popen` (диск недоступен) -> возврат UNC пути.
   - *UI:** При ошибке открытия проводника показывать `ui.notify` с кнопкой копирования пути вида `\\server\share\folder`.

### Фаза 3: Ролевые пути и Полировка (Persona-based)
**Цель:** Идеальный UX и закрытие слепых зон для каждой роли.
1. **UX Оператора:**
   - *Реализация:* Показ всплывающего окна (Dialog) при выборе узла с текстом `handover_note` от предыдущей смены, если она была передана.
   - *Реализация:* Добавление в `PauseDialog` кнопки-чекбокса "Сообщить о проблеме с материалом", интегрированной с `IncidentSystem` или `ChatSystem`.
2. **UX Бригадира:**
   - *Реализация:* Внедрение KPI-виджета "Отставание (Drift %)" прямо над таблицей узлов для быстрого мониторинга.
   - *Реализация:* Активация Cross-links: клик по бейджу батча открывает карточку деталей.

## 5. Стратегия тестирования (TDD Flow)
Для каждого шага применяется следующий цикл:
1. **RED:** Создание тестов в `tests/unit/ui_features/` (например, `test_dynamic_nodes.py`, `test_work_item_filters.py`).
2. **GREEN:** Реализация методов в соответствующих `System`-классах.
3. **REFACTOR:** Интеграция методов в компоненты NiceGUI (`view.py` или `widgets/`) с упором на переиспользование и чистый UI-код.
