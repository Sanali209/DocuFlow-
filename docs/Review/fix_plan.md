# План исправлений по результатам аудита репозитория DocuFlow

Дата: 2026-04-05  
Составил: Cline

Цель: поэтапно устранить блокирующие и критические проблемы, улучшить безопасность, качество кода и CI-процесс.

---

Общий порядок (высокий приоритет сверху):
1. Подготовительный: сделать проект импортируемым (решить ModuleNotFoundError)
2. Очистка репозитория от runtime-артефактов (.db, .env, shared_network)
3. Настроить окружение и прогнать базовые проверки (ruff, pytest)
4. Исправить критические runtime-ошибки (F821 undefined-name)
5. Устранить уязвимости безопасности (hardcoded secrets, Jinja2 autoescape, md5)
6. Исправить try/except:pass, dangling asyncio tasks, loop-variable capture
7. Автофикс стиля (ruff --fix) и ручной ревью изменений
8. Итеративный прогон тестов и исправление оставшихся падений
9. Рефакторинг main.py (реестр view-фабрик)
10. Архивация/удаление устаревших директорий (old mvp, backend*, ...)
11. Финальная проверка, CI и документирование

---

Детализованные шаги

Шаг 1 — Сделать проект импортируемым (блокирует всё)
- Цель: pytest должен импортировать пакет `docuflow`.
- Изменения:
  - В pyproject.toml добавить секцию:
    ```
    [build-system]
    requires = ["hatchling"]
    build-backend = "hatchling.build"
    ```
  - (Опционально) добавить секцию упаковки под выбранный билдер.
- Проверка:
  - python -m pip install -e .
  - python -c "import docuflow; print(docuflow.__file__)"
  - Запуск pytest (ожидаем исчезновения ModuleNotFoundError).
- Оценка: 10–20 минут.

Шаг 2 — Очистка репозитория от runtime-артефактов
- Цель: удалить из репозитория базы данных и runtime-артефакты.
- Изменения:
  - Обновить .gitignore:
    ```
    *.db
    *.env
    shared_network/
    reproduce_issue.py
    ```
  - Удалить из индекса (сохранить локально):
    ```
    git rm --cached *.db *.env src/docuflow/node_01.db
    git rm -r --cached shared_network/
    git commit -m "chore: remove runtime artifacts from repo and update .gitignore"
    ```
- Проверка:
  - git status не показывает удалённых артефактов.
- Внимание: если данные критичны, сначала сделать резервную копию.
- Оценка: 10–30 минут.

Шаг 3 — Установка зависимостей и первичная диагностика
- Цель: подготовить dev-окружение и получить актуальный список проблем.
- Команды:
  - python -m pip install -e .
  - uv run ruff check src/ --statistics
  - uv run pytest -q
- Проверка:
  - pytest не падает только из-за ModuleNotFoundError, ruff выдаёт актуальные ошибки.
- Оценка: 10–30 минут.

Шаг 4 — Исправление критических runtime-ошибок (F821)
- Цель: устранить undefined-name ошибки, которые ломают запуск.
- Основные места для проверки/ремонта:
  - src/docuflow/sdk.py — типы (P2POrchestrator, ProjectSystem, PartLibrarySystem, ...)
    - Перенести импорты типов в блок TYPE_CHECKING либо выполнить явные импорты в runtime, где необходимо.
  - src/docuflow/features/task_board/system.py — импортировать logger
  - src/docuflow/features/parts/view.py — импортировать PartPreviewWidget
  - src/docuflow/features/folder_scanner/view.py — импортировать SDK или использовать TYPE_CHECKING
  - application/bus/orchestrator.py и features/admin/system.py — проверить аннотации HousekeepingSystem, SecureDispatcher
- Подход: маленькими коммитами (по файлу). После правки каждого файла запускать ruff и соответствующие тесты.
- Проверка: F821 исчезают, pytest проходит дальше.
- Оценка: 2–4 часа (зависит от скрытых зависимостей).

Шаг 5 — Устранение проблем безопасности
- Цель: убрать хардкодные пароли/секреты, настроить безопасные шаблоны, заменить/проверить MD5.
- Изменения:
  - Убрать дефолты паролей в bootstrap_admin (переносить в env или требовать аргумент).
  - В reports/system.py: использовать Jinja2 с autoescape:
    ```
    env = Environment(loader=BaseLoader(), autoescape=True)
    ```
  - Заменить использование md5 на hashlib.sha256(), если checksum используется для безопасности.
  - Перенести все секреты в переменные окружения (Config читает DOCUFLOW_...).
- Проверка: ruff/Linter перестают жаловаться на S107/S701/S324; тесты, затрагивающие эти модули, проходят.
- Оценка: 1–3 часа.

Шаг 6 — Исправление анти-паттернов try/except:pass и фоновых задач
- Цель: убрать silent-fails и корректно управлять задачами.
- Изменения:
  - Заменить bare `except: pass` на `except Exception: logger.exception("...")` или узкие except.
  - Сохранять ссылки на задачи: `self._bg_task = asyncio.create_task(...)` и корректно отменять в on_shutdown().
  - Исправить loop-variable capture (B023) — использовать default-аргументы в лямбдах или functools.partial.
- Проверка: ruff предупреждения S110/RUF006/B023 исчезают; функциональные тесты UI и интеграции работают.
- Оценка: 1–3 часа.

Шаг 7 — Автофикс стиля и ревью
- Действия:
  - uv run ruff check src/ --fix
  - Просмотр изменений, ручной ревью особенно строк с русским текстом и длинных строк.
- Проверка: стиль соответствует проектным правилам; тесты прогоняются.
- Оценка: 10–30 минут + ревью.

Шаг 8 — Итеративный прогон тестов и починка падений
- Подход:
  - Запускать тесты по группам: unit → integration → smoke → e2e.
  - Фиксить по мере появления ошибок (инициализация, фикстуры, ожидания).
- Команды:
  - uv run pytest tests/unit -q
  - uv run pytest tests/integration -q
- Оценка: от нескольких часов до нескольких дней.

Шаг 9 — Рефакторинг main.py (реестр view-фабрик)
- Цель: убрать длинный switch_view/elif, упростить добавление новых страниц.
- Изменения:
  - Вынести mapping view_name → factory-асинхронная функция.
  - Убрать inline-импорты в теле switch, расположить их в ленивом реестре или модулях.
- Проверка: UI работает как прежде, smoke tests проходят.
- Оценка: 1–3 часа.

Шаг 10 — Архивация/удаление старого кода
- Цель: уменьшить шум и поддерживать релевантную кодовую базу.
- Действия:
  - Перенести `old mvp/`, `backendrouters/`, `backend/` (если не используется) в `archive/` или в отдельную ветку.
  - Обсудить с командой перед удалением.
- Оценка: 30–90 минут (зависит от объёма и согласований).

Шаг 11 — Финальная проверка и документирование
- Действия:
  - uv run ruff check src/ (0 ошибок)
  - uv run mypy src (при необходимости)
  - uv run pytest -q (все тесты)
  - Обновить docs/Review с итогами
- Оценка: 1–4 часа.

Риски и замечания
- Операция удаления файлов из репозитория изменит индекс; если хотите сохранить бэкап — сделать архивацию перед удалением.
- Некоторые автоматические правки ruff могут изменить строки на кириллице; просмотреть вручную.
- Исправления могут выявить дополнительные проблемы — план подразумевает итеративную работу.
