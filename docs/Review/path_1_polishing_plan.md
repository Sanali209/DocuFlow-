# План реализации Пути 1 (Финальная полировка DocuFlow v3.1+)

## 🎯 Описание этапа
Этот этап (The "Last 5%") направлен на устранение оставшихся логических пробелов и повышение общей надежности системы перед полноценным релизом. Основной фокус на автоматизации процессов и защите от пользовательских ошибок.

## 🛠 Задачи

### 1. Авто-закрытие нарядов (WorkItem Auto-Complete)
**Проблема:** Сейчас при завершении последней задачи наряда оператором сам наряд остается в статусе "В работе", пока бригадир не закроет его вручную (что даже не предусмотрено в UI).
**Решение:**
- В `TaskBoardSystem.complete_task` после обновления статуса задачи добавить проверку всех задач (TaskItem) этого наряда.
- Если все задачи наряда имеют статус `DONE` или `CANCELLED`, автоматически менять статус `WorkItem.status` на `DONE`, проставлять `completed_at` и писать лог "Наряд автоматически закрыт".

### 2. Защита склада "от дурака" (Hard Block Negative Stock)
**Проблема:** В `InventorySystem.perform_write_off` нет блокировки списания в минус. При ошибке ввода оператора остатки могут стать отрицательными.
**Решение:**
- Модифицировать метод `perform_write_off`: перед вычитанием `sheets_used` проверять доступное количество в партии.
- Если запрашиваемое количество больше остатка, либо искать следующую партию (FIFO), либо выбрасывать `ValueError` ("Недостаточно материала на складе"), блокируя завершение задачи.

### 3. Визуальный Аудит (System Event Log)
**Проблема:** Администратор не имеет единого дашборда для просмотра всех событий в системе (кто когда логинился, кто какие задачи начинал, какие инциденты происходили).
**Решение:**
- В разделе "System Admin" (`admin/view.py`) добавить новую вкладку "SYSTEM LOG" (Визуальный аудит).
- Реализовать отображение глобального `WorkLog` в виде ленты событий (Timeline) в стиле соцсетей: с аватарками авторов, тегами типов логов (INFO, WARNING, ERROR) и фильтрацией по времени/пользователю.
