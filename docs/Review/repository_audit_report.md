# Аудит репозитория DocuFlow

Дата: 2026-04-05

Автор: Cline (автоматически сгенерированный технический аудит)

## Краткое резюме

- Общее состояние: частично рабочее, но есть критические блокирующие проблемы.
- Критические находки:
  - Пакет не собирается/не устанавливается как Python-пакет → pytest не может импортировать `docuflow`.
  - В репозитории закоммичены runtime-артефакты (SQLite БД, env-файлы, shared_network) — риск утечки данных/секретов.
- Количество найденных проблем в коде (ruff): 212 ошибок в `src/`. Из них несколько — критические (F821 undefined-name и т.п.).
- Безопасность: хардкоженные пароли/секреты, использование MD5 в checksum, Jinja2 без autoescape в одном месте.
- Сильные стороны: вертикальная архитектура (vertical-slices), атомарные записи в FileBus, централизованные константы, хорошая тестовая база (много тестов покрывающих разные уровни).

## Детальный отчет

### 1) Блокирующая проблема: пакет/установка (CRITICAL)
Проблема:
- В проекте отсутствует секция `[build-system]` в `pyproject.toml`. Из-за этого пакет `docuflow` не устанавливается в окружение, что приводит к ошибкам типа `ModuleNotFoundError: No module named 'docuflow'` при запуске pytest.

Влияние:
- Невозможно запустить тесты и локально импортировать пакет.

Решение (рекомендуется добавить в pyproject.toml):
```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"
```
Опционально (при использовании hatch/hatchling) — добавить target/packaging секцию. После правки:
```bash
uv sync
uv run pip install -e .
# или просто
python -m pip install -e .
```

### 2) Файлы, не принадлежащие репозиторию (HIGH)
Найдены закоммиченные runtime-файлы:
- `docuflow.db`, `local.db`, `node_01.db`, `TEST_ORCH.db`, `src/docuflow/node_01.db` — SQLite БД
- `node_01.env`, `node_02.env` — env файлы
- `shared_network/` (локальные runtime артефакты: HEARTBEATS, SNAPSHOTS, lock-файлы)
- `reproduce_issue.py`

Риск:
- Утечка пользовательских данных, паролей, ключей.
- Загромождение репозитория.

Рекомендации:
1. Добавить в `.gitignore` строки:
```
*.db
*.env
shared_network/
reproduce_issue.py
```
2. Удалить файлы из индекса git, сохранив локально:
```bash
git rm --cached *.db *.env reproduce_issue.py
git rm -r --cached shared_network/
git commit -m "chore: remove runtime artifacts from repo"
```
3. Если необходимо полностью стереть исторические артефакты из истории — использовать `git filter-repo` / `bfg` (операция деструктивная — делать только при необходимости).

### 3) Lint / Статический анализ (MEDIUM → HIGH частично)
Результаты ruff по `src/`:
- Всего найдено 212 ошибок.
- Критические классы ошибок:
  - F821 (undefined-name): несколько мест, которые ломают runtime (например, отсутствующие импорты `logger`, `PartPreviewWidget`, типы в аннотациях).
  - RUF006 (dangling asyncio task): запуск фоновой задачи без сохранения ссылки.
  - B023 (loop variable capture) — баги в UI-коллбеках.
  - S-type (security) — hardcoded secrets, использование MD5.

Рекомендации:
- Сначала исправить F821 (undefined name), т.к. они ломают выполнение.
- Затем запустить `ruff check --fix` для автоисправляемых проблем и вручную пройти по оставшимся.
- Проверить и поправить `asyncio.create_task` — хранить возвращаемую задачу или использовать явное управление.

---

### 4) Безопасность (HIGH)
Найденные проблемы:
- S107: Hardcoded default passwords, например:
  - `bootstrap_admin(default_password="docuflow_admin")` в нескольких местах.
- S701: Jinja2 Environment создан без autoescape — риск XSS в отчетах (`reports/system.py`).
- S324: MD5 используется для контрольной суммы файлов — лучше заменить на SHA-256 (если безопасность важна).
- Захардкоженные storage secrets:
  - `main.py` использует `storage_secret="docuflow_nicegui_shh"`.
  - `config.py` содержит `storage_secret = "docuflow_secret_change_me"`.

Рекомендации:
- Удалить все дефолтные пароли из кода. Оставлять `None` и требовать значения через env или интерфейс.
- Jinja2: создать environment с autoescape:
  ```python
  env = Environment(loader=BaseLoader(), autoescape=True)
  ```
- Заменить MD5 на hashlib.sha256() если checksum используется для безопасности/подписей. Если это только для дедупликации/скорости — документировать причину выбора MD5.
- Перенести секреты в переменные окружения и добавить проверку наличия на старте (fail-fast).

---

### 5) Архитектурные замечания (MEDIUM)
- `main.py` — большая монолитная страница роутинга с множеством inline-импортов и ветвлений `elif`. Лучше вынести реестр view-фабрик и уменьшить повторяющийся код.
- `sdk.py` использует `hasattr` для проверки инициализации сервисов; лучше инициализировать в `__init__` или иметь явную фазу `initialize()`.
- `di.py` вручную кеширует SDK экземпляр в провайдере. Dishka скоуп APP уже делает это; ручное кеширование можно убрать.
- Есть устаревшие каталоги: `old mvp/`, `backend/`, `backendrouters/`. Решить, что оставить, что удалить или переместить.

## Конкретные критические правки (порядок исправления)

1. Добавить `[build-system]` в `pyproject.toml` и установить пакет в editable-режиме.
2. Обновить `.gitignore` и удалить runtime-артефакты из git-индекса.
3. Исправить F821 undefined-name:
   - импортировать `logger` в модулях, где он используется;
   - импортировать `PartPreviewWidget` в `features/parts/view.py`;
   - добавить недостающие типы/аннотации в `TYPE_CHECKING` или явные импорты.
4. Убрать хардкоженные пароли и секреты; подтолкнуть чтение из переменных окружения.
5. Исправить Jinja2 `autoescape`.
6. Исправить использование MD5 (на SHA256) или документировать/оставить если это только для checksum без требований безопасности.
7. Заменить `except: pass` на логирование (logger.exception / logger.debug).
8. Рефакторинг `main.py` на реестр view → уменьшение ветвлений.
