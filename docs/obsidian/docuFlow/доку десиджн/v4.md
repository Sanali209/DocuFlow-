### A2. Операционный цикл цеха

Весь жизненный цикл разбит на 8 этапов. Каждый этап = один или несколько модулей:

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. ПОЛУЧЕНИЕ РАБОТЫ                                             │
│    Сканер → FolderScanner обнаруживает папку                   │
│    Оповещение бригадира → панель "Новые наряды"                │
├─────────────────────────────────────────────────────────────────┤
│ 2. ПОДГОТОВКА К РАБОТЕ                                         │
│    Бригадир: проверка материалов → Reservation                 │
│    Батчинг → группировка TaskItem по материалу                 │
│    Проверка запаса → алерт "деталь уже есть"                   │
├─────────────────────────────────────────────────────────────────┤
│ 3. ПРИЁМ В РАБОТУ (ОПЕРАТОР)                                   │
│    Оператор видит свою "корзину" (WorkerBucket)                │
│    Берёт TaskItem → FileBus REQ lock_batch                     │
│    Мастер подтверждает → статус "in_progress"                  │
├─────────────────────────────────────────────────────────────────┤
│ 4. ВЫПОЛНЕНИЕ / МОНИТОРИНГ                                     │
│    Оператор: отметить шаги                                     │
│    Бригадир: вид "что делается прямо сейчас" (all nodes)       │
│    Тайм-трекинг, паузы, причины остановки → WorkLog            │
├─────────────────────────────────────────────────────────────────┤
│ 5. ЗАВЕРШЕНИЕ И УЧЁТ                                           │
│    TaskItem → DONE → создать ProductionUnit (паллета)          │
│    Оператор указывает StorageLocation ("куда положили")        │
│    MaterialStock: фактическое списание листов                  │
├─────────────────────────────────────────────────────────────────┤
│ 6. СКЛАДИРОВАНИЕ                                               │
│    ProductionUnit привязан к StorageLocation                   │
│    QR/Label генерация для паллеты                              │
│    Кладовщик: поиск "где лежат детали из наряда X"             │
├─────────────────────────────────────────────────────────────────┤
│ 7. РЕТРОСПЕКТИВНЫЙ ПОИСК                                       │
│    PartLibrary: поиск по SKU, габаритам, материалу             │
│    "В каких нарядах встречается деталь 3433-11-004-G?"         │
│    "Есть ли эта деталь в запасе?"                              │
├─────────────────────────────────────────────────────────────────┤
│ 8. УПРАВЛЕНИЕ СКЛАДОМ МАТЕРИАЛОВ                               │
│    MaterialStock: приход, резерв, списание                     │
│    MaterialAudit: кто, когда, сколько, на основании чего       │
│    Передача смены: WorkerBucket handover                       │
└─────────────────────────────────────────────────────────────────┘
```

# ═══════════════════════════ PROJECTS ═══════════════════════════

class Project(BaseEntity, table=True):
    """Верхний контейнер: 'SHLAV-2', 'Default', 'Ремонт авт. 777'"""
    name: str = Field(unique=True, index=True)
    description: Optional[str] = None
    is_default: bool = Field(default=False)   # Один Default всегда существует
    status: str = Field(default="active")
    work_items: List["WorkItem"] = Relationship(back_populates="project")


# ═══════════════════════════ WORK ITEMS ═════════════════════════

class WorkItemType(str, Enum):
    SIDRA  = "sidra"   # Плановый наряд
    MIHTAV = "mihtav"  # Письмо / внеплановый заказ
    REWORK = "rework"  # Доработка (не "Портачка")

class WorkItemStatus(str, Enum):
    NEW            = "new"             # Папка найдена сканером
    FOLDER_NO_DOC  = "folder_no_doc"   # Папка есть, физ. документ не получен
    DOC_NO_FOLDER  = "doc_no_folder"   # Физ. документ получен, папки нет
    REGISTERED     = "registered"      # Документ + папка подтверждены
    IN_PROGRESS    = "in_progress"
    ON_HOLD        = "on_hold"         # Приостановлено (причина в WorkLog)
    DONE           = "done"
    ARCHIVED       = "archived"

class WorkItem(BaseEntity, table=True):
    project_id: int = Field(foreign_key="project.id", index=True)
    work_item_type: WorkItemType
    status: WorkItemStatus = WorkItemStatus.NEW

    # Идентификация (ключ идемпотентности для сканера)
    folder_name: str = Field(unique=True, index=True)
    folder_path: str   # Относительный путь (буквонезависимый!)

    sidra_number: Optional[str] = None   # "353203"
    sidra_step: Optional[str] = None     # "SHLAV-2" (шаг наряда, не проект!)

    # Временны́е метки жизненного цикла
    folder_found_at: datetime = Field(default_factory=datetime.now)
    doc_received_at: Optional[datetime] = None   # Когда физ. документ получен

class TaskItemStatus(str, Enum):

class TaskItem(BaseEntity, table=True):
    """Один GNC файл = одна задача резки."""
    work_item_id: int = Field(foreign_key="workitem.id", index=True)
    mat_type_id: Optional[int] = Field(default=None, foreign_key="materialtype.id")
    status: TaskItemStatus = TaskItemStatus.PLANNED
    priority: int = Field(default=0)      # 0=normal, 1=high, 2=critical
    is_urgent: bool = Field(default=False)

    # Файл (буквонезависимый путь)
    file_name: str
    file_path: str    # ОТНОСИТЕЛЬНЫЙ от scan root (не абс. путь!)
    file_hash: str    # MD5 — детекция изменений

    # Из *SHEET в GNC

    sheet_y: Optional[float] = None
    sheet_qty: Optional[int] = None       # Кол-во листов

class TaskPart(BaseEntity, table=True):

## ЧАСТЬ C: FolderScanner (детали реализации)

### C1. SKU-парсинг (исправленный)

```
PART NAME raw: "3433-11-004-G-1"
                     │       │ │
                     SKU     │ └─ Неизвестный суффикс (цифра, назначение TBD)
                             └─── "G" = buква версии (последний alpha-сегмент)

Parsing logic:
segments = "3433-11-004-G-1".split("-")
# → ["3433", "11", "004", "G", "1"]

# Находим последний буквенный сегмент = версия
version = last alpha segment = "G"
# Всё до версии = SKU base
sku = "3433-11-004"
version_suffix = "1"  # всё после версии (назначение неизвестно, сохраняем)

# Финальный SKU для PartLibrary.sku:
sku = "3433-11-004-G"   # base + version буква
```

**Важно:** `PART SIZE` в GNC — это bbox **всего нестa**, не отдельной детали.
Для точных габаритов детали нужен **парсинг G-кода контуров** (из MVP SVGGenerator).
GNCParser уже считает `corner_count` по контурам — это нужно сохранять в `PartLibrary`.

### C3. Алгоритм сканирования (кратко)

```
MASTER ONLY — async polling loop:
  FOR path IN [sidra_path, mihtav_path]:
    FOR folder IN path.iterdir():
      work_item = db.get_by_folder_name(folder.name) OR create_new(folder)
      → project = find_project(sidra_step) OR use_default_project

      FOR gnc IN folder/*.GNC WHERE NOT is_variant(gnc):
        hash_now = md5(gnc)
        task = db.get_task(gnc.path)

        IF task AND task.hash != hash_now:
          → log FILE_CHANGED + broadcast alert → notify operator

        parse_gnc(gnc) → MaterialType (create if new) + TaskItem + TaskPart[]
        db.upsert_part_library(sku)  ← из (PART NAME:...) в GNC
```

## Открытые вопросы

> [!NOTE]
> **Q1: version_suffix в SKU** (`3433-11-004-G-1` → суффикс "1")**
> Что означает цифра после буквы версии? Инкремент версии? Номер экземпляра?
> Пока: сохраняем в `TaskPart.version_suffix`, не используем для идентификации.

> [!NOTE]
> **Q2: PART SIZE vs реальный bbox детали**
> `(PART SIZE=3201.25 X 1136.361)` — это bbox нестa целиком, не детали.
> Для `PartLibrary.bbox_x/y` нужен парсинг G-кода контуров (восстановление внешнего контура).
> SVGGenerator из MVP это умеет. Включаем в Фазу 1 или Фазу 3?

> [!NOTE]
> **Q3: ChatMessage синхронизация**
> Чат синхронизируется через FileBus broadcast или через snapshot?
> Рекомендация: через FileBus broadcast (быстро, не нужна история после рестарта).
> Или хранить в БД для истории?

> [!IMPORTANT]
> **Q4: WorkerBucket — один или много TaskItem одновременно?**
> Может ли оператор взять несколько TaskItem в корзину сразу?
> Или корзина = всегда один активный TaskItem?
