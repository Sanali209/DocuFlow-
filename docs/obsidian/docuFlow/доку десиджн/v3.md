# DocuFlow — FolderScanner & Domain Model: Implementation Plan v3

## Ключевые решения (окончательно)

| Вопрос | Решение |
|---|---|
| Источник данных | Только `.GNC`, `_AUT.TXT` — игнорируем |
| Пути к папкам | **LOCAL env** переменные на каждом узле (буква диска разная!) |
| Кто сканирует | Только **мастер-узел** |
| Триггер | **Periodic polling** (async loop) |
| Папки не перемещаем | Статус → БД |
| Неидентифицированные WorkItem | Автоматически → **Проект "Default"** |
| WorkItemType | `SIDRA` \| `MIHTAV` \| `REWORK` |
| Нест → переименовать | **`TaskItem`** |
| SKU детали | Только артикул: strip path + ext + version suffix |

## 1. Точный формат GNC (реальный sample)

```gnc
(CK-AN Post V22.1 SP383  run on JUL 07 2025)    ← пост-процессор
(*MODEL HANS_G3015-REXROTH)                       ← модель МАШИНЫ (не проекта!)
(1  PARTS)                                         ← кол-во деталей
(DATE JUL 07 2025)
(*SHEET 3250.0 1250.0 3.0 7 1 0.0 0.0 )           ← КЛЮЧЕВАЯ строка
  │          │      │   │  │
  │     sheet_x  sheet_y │  cut_count (7 листов)
  │              thickness  batch_idx (1)
(Material:AA 5052-H32)                             ← марка материала
(THICKNESS=3.0)                                    ← дублирует *SHEET
(PART SIZE=3201.25  X 1136.361)                    ← bounding box детали
(SHEET SIZE=3250.0 ,1250.0)                        ← дублирует *SHEET

(*****Part info*****)
(PART NAME:3433-11-004-G-1 )                       ← артикул + версия
  │         │              │
  │      SKU базовый       └─ version suffix (последний символ)
  └─ "3433-11-004-G" = SKU, "1" = version

(==== CONTOUR 1 ====)                              ← начало контура
N1005 G00X971Y485.361 ...                          ← G-код
```

**Парсинг `*MODEL`**: Это имя **машины** (HANS_G3015-REXROTH), НЕ шага проекта.
**Шаг**: извлекается из **имени папки** (SHLAV-2 в SIDRA-353203-**SHLAV-2**-07.07.2025).

**Парсинг SKU** из `(PART NAME:3433-11-004-G-1 )`:
```python
raw = "3433-11-004-G-1"
# Последний сегмент после последнего "-" если это цифра = version
parts = raw.rsplit("-", 1)
if parts[-1].isdigit():
    sku, version = parts[0], parts[1]
else:
    sku, version = raw, "A"
# sku = "3433-11-004-G", version = "1"
```

## 3. Полная ERD — доменные сущности

### 3.1 Иерархия производства

```
Project (Контейнер верхнего уровня — "20 автобусов Apollo")
  └── WorkItem[] (Конкретный документ — Сидра, Письмо, Доработка)
        └── TaskItem[] (Один GNC файл — "нест" с материалом)
              └── TaskPart[] (Деталь в таске: SKU + кол-во)
                    └── PartLibrary (Справочник: что это за деталь)

MaterialType (Библиотека типов материала)
  └── MaterialStock[] (Конкретные листы/пачки на складе)
        └── Reservation[] (Резерв под WorkItem)

TaskItem → (производство) → ProductionUnit (Паллета/корзина готовых деталей)
  └── StorageLocation (Место складирования)

WorkItem / TaskItem → WorkLog[] (Журнал трассировки)
```

## 4. Паттерны парсинга

### 4.1 FolderNameParser

```python
# SIDRA паттерн (не всегда соблюдается — нужен fallback!)
SIDRA_REGEX = re.compile(
    r'^SIDRA-(?P<number>\d+)-(?P<step>.+?)-(?P<day>\d{2})\.(?P<month>\d{2})\.(?P<year>\d{4})$',
    re.IGNORECASE
)

def parse_folder_name(name: str) -> FolderMeta:
    m = SIDRA_REGEX.match(name)
    if m:
        return FolderMeta(
            work_item_type=WorkItemType.SIDRA,
            sidra_number=m.group("number"),
            sidra_step=m.group("step"),          # "SHLAV-2" = шаг наряда
            project_hint=m.group("step"),         # используем для поиска Project
            doc_date=date(int(m.group("year")), int(m.group("month")), int(m.group("day")))
        )
    # Fallback: не распознали структуру — MIHTAV или нестандартная SIDRA
    return FolderMeta(
        work_item_type=WorkItemType.MIHTAV,
        project_hint=None,   # → будет привязан к "Default" проекту
    )
```

### 4.2 SKU из PART NAME

```python
def extract_sku(part_name_raw: str) -> tuple[str, str]:
    """
    Input:  "3433-11-004-G-1 " (с возможными пробелами, путями)
    Output: ("3433-11-004-G", "1")
    """
    # Убираем путь (если есть \\server\path\...)
    name = part_name_raw.strip().split("\\")[-1]
    # Убираем расширение (.dft, .DFT)
    name = re.sub(r'\.\w+$', '', name).strip()
    # Разбиваем по последнему "-"
    parts = name.rsplit("-", 1)
    if len(parts) == 2 and parts[1].isdigit():
        return parts[0], parts[1]
    return name, "A"
```

### 4.3 Хранение путей (буквонезависимость)

```python
# При сканировании: сохраняем ОТНОСИТЕЛЬНЫЙ путь
def to_relative_path(abs_path: str, scan_root: str) -> str:
    return str(Path(abs_path).relative_to(scan_root))

# При доступе к файлу: восстанавливаем через env
def resolve_path(relative_path: str, scan_root: str) -> Path:
    return Path(scan_root) / relative_path
```

### 4.4 Детекция изменения файла

```python
def compute_hash(file_path: Path) -> str:
    return hashlib.md5(file_path.read_bytes()).hexdigest()

def check_file_changes(task_item: TaskItem, scan_root: str, session, orchestrator):
    abs_path = resolve_path(task_item.file_path, scan_root)
    new_hash = compute_hash(abs_path)
    if new_hash != task_item.file_hash:
        # 1. Обновить хэш
        old_hash = task_item.file_hash
        task_item.file_hash = new_hash
        # 2. Записать в WorkLog (ВАЖНО — сразу)
        log = WorkLog(
            task_item_id=task_item.id,
            log_type=WorkLogType.FILE_CHANGED,
            author="system",
            message=f"GNC file changed: {task_item.file_name}",
            payload=json.dumps({"old_hash": old_hash, "new_hash": new_hash})
        )
        session.add(log)
        # 3. Broadcast уведомление оператору/бригадиру через FileBus
        orchestrator.broadcast_command("FILE_CHANGED_ALERT", {
            "task_item_id": task_item.id,
            "file_name": task_item.file_name,
        })
```

## 5. Batching Engine (концепция)

> [!NOTE]
> **Batching Engine** — отдельный модуль, не часть сканера.
> Сканер только наполняет данные. Батчинг — отдельная логика.

### 5.1 Концепция правил батчинга

```python
# Пример стандартного правила (из review):
DEFAULT_RULE = BatchRule(
    name="Standard",
    match_same_material_code=True,
    match_same_thickness=True,
    match_same_sheet_size=True,
    match_same_work_item=False,   # из разных нарядов — ок!
)
```

### 5.2 Рекомендации системы

При создании/редактировании батча система показывает:
- **"Добавить в батч?"** — TaskItem из других нарядов с тем же материалом/толщиной/размером
- **⚠️ "Деталь в запасе!"** — если в `ProductionUnit(is_stock=True)` есть детали из этого TaskItem → предложить использовать запас, не резать

## 6. Поиск деталей (прямой и обратный)

```
ПРЯМОЙ: "Есть ли деталь 3433-11-004-G в наряде SIDRA-353203?"
  PartLibrary.sku → TaskPart → TaskItem → WorkItem (filter by folder_name)

ОБРАТНЫЙ: "В каких нарядах / проектах встречается деталь 3433-11-004-G?"
  PartLibrary.sku → TaskPart[] → TaskItem[] → WorkItem[] → Project[]

ПОИСК по габаритам (с допуском):
  SELECT * FROM partlibrary
  WHERE bbox_x BETWEEN :x_min AND :x_max
  AND   bbox_y BETWEEN :y_min AND :y_max
  AND   mat_type_id = :type

ПОИСК по кол-ву отверстий / контуров:
  WHERE hole_count = :holes AND corner_count BETWEEN :min AND :max
```
