Вопрос авторизации в P2P-системе, где «сервер» постоянно мигрирует, — это вызов. Традиционный подход с Sessions или JWT-токенами, хранящимися в памяти одного сервера, здесь не сработает.

Нам нужна **децентрализованная авторизация**, основанная на «Общей Правде» (Master DB), которая кочует вместе с Координатором.

---

## 1. Децентрализованная Авторизация (RBAC)

Разграничение ролей (**Role-Based Access Control**) должно быть зашито в саму структуру `User` в базе данных. Поскольку база (`master.db`) синхронизируется между узлами, любой узел в любой момент знает, кто такой «Иван Петров» и на что он имеет право.

### Структура модели User:

Python

```
class User(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    username: str = Field(unique=True, index=True)
    password_hash: str
    role: str = Field(default="worker") # "worker", "foreman", "admin"
    node_binding: Optional[str] = None # Привязка к конкретному лазеру (опционально)
```

**Механика входа:**

1. Пользователь вводит логин/пароль на любом терминале (NiceGUI).

2. Узел проверяет хэш пароля по своей `local.db` (которая является актуальным слепком мастера).

3. Если ок — узел создает **Локальную Сессию** (в памяти FastAPI/NiceGUI).

4. Все действия (REQ) в шину подписываются `user_id`.


---

## 2. Панель Администрирования (Универсальный пульт)

Админка в твоем SDK — это не отдельный сайт, а **специальный режим интерфейса NiceGUI**, доступный пользователям с ролью `admin`.

### Управление P2P Координатором:

Поскольку любой узел может стать мастером, админка должна уметь «дергать рычаги» кластера через шину:

- **Forced Election:** Админ может отправить команду `FORCE_STEP_DOWN` через диспетчер. Текущий Координатор, получив её, обязан удалить свой `.coordinator.lock` и уступить место.

- **Cluster Health:** Админ видит список всех `node_{node_id}.json` в папке `/HEARTBEATS` и время их последнего «пульса».

- **DB Management:** Кнопка «Сделать принудительный Snapshot» или «Откатиться к версии X».


---

## 3. Управление с любого места (Anywhere Access)

Чтобы ты мог управлять заводом из кабинета или через VPN, не подходя к лазеру:

1. Ты запускаешь тот же самый код (FastAPI + SDK) на своем рабочем ПК.

2. Твой ПК становится еще одним **Узлом** в P2P сети.

3. Ты авторизуешься как `admin`.

4. Твой узел читает ту же Samba-папку. Ты видишь всё, что происходит в цеху в реальном времени.

## 4. Как это вписывается в SDK (Блокатор)

Авторизация становится **Middleware** или **Depends** в твоем FastAPI приложении.

Python

```
def get_current_user(request: Request):
    user = request.session.get("user")
    if not user:
        raise HTTPException(status_code=401)
    return user

@app.post("/admin/reboot-cluster")
async def reboot_cluster(user: User = Depends(get_current_user), sdk: FactorySDK = Depends(get_sdk)):
    if user.role != "admin":
        raise HTTPException(status_code=403, detail="Только для админов")

    # Пишем в шину команду на перевыборы
    await sdk.bus.send_broadcast_command("REBOOT_COORDINATOR")
```

## 5. Безопасность в P2P

Поскольку файлы в Samba лежат открыто, есть риск, что кто-то «умный» подкинет файл `REQ_...` вручную.

- **Решение:** Каждое сообщение `P2PMessage` содержит поле `signature` — HMAC-хэш от данных запроса, подписанный секретным ключом завода (который лежит в «холодном» конфиге `.env` на всех узлах).

- **Координатор:** Если подпись в сообщении не совпадает или пакет поврежден — сообщение игнорируется и удаляется.


### Резюме по админке:

- **Роли:** Хранятся в синхронизируемой базе.

- **Вход:** На любом узле через локальную сверку.

- **Управление:** Через специальные сообщения в шине, которые понимает Координатор.

- **Мониторинг:** Визуализация папки `/BUS` и `/CLUSTER` в красивом интерфейсе NiceGUI.


Для реализации такой гибкой системы на базе **P2P-узлов**, **FastAPI** и **NiceGUI**, нам нужно разделить авторизацию на два уровня: **Физический (Узел/Рабочее место)** и **Логический (Пользователь/Роль)**.

Правильный подход — использовать **Компонентную сборку интерфейса**. Сервер (Узел) не просто отдает страницу, а «собирает» её из кирпичков-модулей, проверяя права текущей сессии.

### 5. Управление P2P Координатором через Админку

Админ — единственный, у кого в интерфейсе есть вкладка **«Состояние Сети»**. Там он видит:

- **Список узлов:** Какие компы в сети (Heartbeat из папки `/HEARTBEATS`).

- **Кто Мастер:** Подсветка узла, который сейчас держит `.coordinator.lock`.

- **Кнопка «Сбросить Лидера»:** Если админ видит, что мастер-узел тормозит, он посылает сигнал `FORCE_STEP_DOWN`.

- **Синхронизация:** Статус последнего бэкапа базы в Samba.


### Итог для твоего SDK:

1. **Админ** создает «сетку» завода (Рабочие места) и «список людей» (Пользователи).

2. **Контракты** (Permissions) связывают их.

3. **P2P-шина** разносит эти настройки по всем узлам через синхронизацию `master.db`.

4. **NiceGUI** реактивно перестраивает экран под каждого залогинившегося человека.


**Хочешь, пропишем механизм "Блокировки интерфейса", если на данное рабочее место зашел человек, которому в базе запрещено работать именно за этим узлом?**

Чистим архитектуру от «воды» и фиксируем финальную логику. Вот твоя консолидированная система авторизации и управления для P2P-завода.

---

### 1. Архитектурная база: «Личность + Точка»

Авторизация работает на пересечении двух сущностей: **User** (права человека) и **Workplace** (возможности железа).

- **Где правда:** В `master.db`. Все изменения (новый юзер, смена прав рабочего места) идут через `REQ` в шину.

- **Где проверка:** В `local.db`. Каждый узел мгновенно валидирует логин, используя свой актуальный слепок мастера.

- **Сессия:** Локальная в рамках FastAPI-процесса. Подпись каждого `REQ` файла связкой `User_ID + Node_ID + Signature`.


---

### 2. Модель данных (Single Source of Truth)

Используем `SQLModel` для описания прав.

Python

```
from typing import List, Optional
import json
from sqlmodel import SQLModel, Field

class Workplace(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    node_id: str = Field(index=True)  # Физический ID (напр. LASER_01)
    name: str                         # Название для людей
    allowed_modules: str              # JSON ["tracking", "inventory"]

class Role(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    name: str                         # Admin, Operator, Foreman
    permissions: str                  # JSON ["can_edit_tasks", "can_view_reports"]

class User(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    username: str = Field(unique=True)
    password_hash: str
    role_id: int = Field(foreign_key="role.id")
    allowed_workplaces: str           # JSON [1, 2] - список ID доступных мест
```

### 3. Механизм «Блокатора» интерфейса

Интерфейс NiceGUI собирается динамически. Если условия не соблюдены, пользователь видит экран блокировки.

Python

```
def check_access(user: User, workplace: Workplace) -> bool:
    # 1. Может ли этот человек работать здесь?
    allowed_ids = json.loads(user.allowed_workplaces)
    if workplace.id not in allowed_ids and user.role_name != "Admin":
        return False
    return True

def get_active_ui_modules(user: User, workplace: Workplace):
    # Пересечение прав роли и возможностей места
    user_perms = set(json.loads(user.role.permissions))
    wp_mods = set(json.loads(workplace.allowed_modules))

    if user.role_name == "Admin": return wp_mods # Админ видит всё, что есть на узле
    return user_perms.intersection(wp_mods)
```

### 4. Панель администрирования (Master Control)

Доступна только с `role.name == "Admin"`. Работает как «пульт управления кластером».

- **Управление людьми:** Форма создания `User`, выбор `Role` и чекбоксы доступных `Workplace`.

- **Конфиг цеха:** Редактор `Workplace`. Выбираем `node_id` (из списка живых узлов в `/HEARTBEATS`) и включаем нужные модули (Склад, Планирование и т.д.).

- **P2P Статус:**

    - **Health:** Кто сейчас Лидер, время последнего снапшота базы.

    - **Force Step Down:** Кнопка принудительной передачи роли Координатора другому узлу.

    - **Sync Status:** Визуализация очереди файлов в `/BUS`.

### 5. Безопасность (HMAC Signature)

Чтобы никто не подкинул файл в Samba вручную, SDK подписывает каждый запрос.

import hmac, hashlib

def sign_request(signable_content: str, secret_key: str):
    return hmac.new(secret_key.encode(), signable_content.encode(), hashlib.sha256).hexdigest()

### Итог системы

1. **Узел автономен:** Логинит пользователя по локальной базе.

2. **Интерфейс адаптивен:** Показывает только те модули, которые разрешены **и** пользователю, **и** этому рабочему месту.

3. **Админка универсальна:** Позволяет с любого узла (при наличии прав) перекроить карту прав всего завода.

4. **Координатор исполняет:** Все изменения прав разлетаются по цеху через синхронизацию `master.db`.
