Идея с **динамическим Координатором (Leader Election)** — это отличное решение для условий цеха. Это превращает систему из клиент-серверной в настоящую **децентрализованную сеть**, где выход из строя любого компьютера (даже «главного») не останавливает работу.

### Как это будет работать (вкратце):

1. **Выборы через «Шину»**: Мы будем использовать атомарное переименование файлов на Samba (`os.rename`). Узел, который первым успеет переименовать свой временный файл в `.coordinator.lock`, становится главным.
2. **Пульс (Heartbeat)**: Координатор каждые 15 секунд обновляет метку времени в этом файле. Если метка не обновлялась больше 45 секунд — значит, узел «упал», и другие узлы начинают новые выборы.
3. **Общая база (Master DB)**: Чтобы любой узел мог подхватить работу, файл `master.db` (мастер-база SQLite) должен лежать в общаке на Samba. К нему подключается **только** активный Координатор.
4. **Автономность**: У каждого узла остается своя `local.db` для моментальной работы интерфейса NiceGUI. Синхронизация с мастером идет в фоновом режиме через те же JSON-файлы.

### Критический нюанс:

Работа SQLite через сетевую папку (Samba) требует осторожности. Мы должны использовать режим **WAL (Write-Ahead Logging)** и гарантировать, что **только один** процесс пишет в базу, иначе она может «биться». Механизм блокировки (`.coordinator.lock`) здесь становится критически важным.
